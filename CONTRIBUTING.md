# Contributing

Thanks for improving the template. Keep changes focused, preserve the repository boundary, and do not add product-specific behavior to the starter.

1. Create a branch from `main`.
2. Install with `corepack yarn install --immutable`.
3. Keep contracts, services, presenters, components, copy, and tests synchronized.
4. Run `corepack yarn check` before opening a pull request.
5. Describe behavior changes, security implications, and manual verification in the pull request.

Do not commit credentials, local environment files, generated output, or copied production data. For a vulnerability, use the private process in `SECURITY.md`.
